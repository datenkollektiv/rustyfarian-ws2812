# Release Plan — 0.2.0 — 2026-03-01

**Branch:** `main`
**Pre-flight reference:** `release/2026-03-01-0.2.0-preflight.md`

## Steps

### 1. Bump all crate versions to 0.2.0

Edit each file — change `version = "0.1.x"` to `version = "0.2.0"`:

- `crates/ws2812-pure/Cargo.toml`
- `crates/ferriswheel/Cargo.toml`
- `crates/led-effects/Cargo.toml`
- `crates/rustyfarian-esp-idf-ws2812/Cargo.toml`
- `crates/rustyfarian-esp-hal-ws2812/Cargo.toml`

### 2. Finalize CHANGELOG.md

**File:** `CHANGELOG.md`

Replace the top of the file:

```
## [Unreleased]
```

with:

```
## [Unreleased]

## [0.2.0] - 2026-03-01
```

This preserves a fresh `[Unreleased]` section for the next cycle.

### 3. Verify the build is still clean

```sh
just pre-commit
```

### 4. Commit the release

```sh
git add crates/ws2812-pure/Cargo.toml \
        crates/ferriswheel/Cargo.toml \
        crates/led-effects/Cargo.toml \
        crates/rustyfarian-esp-idf-ws2812/Cargo.toml \
        crates/rustyfarian-esp-hal-ws2812/Cargo.toml \
        CHANGELOG.md
git commit -m "chore(release): v0.2.0"
```

### 5. Tag the release

```sh
git tag -a v0.2.0 -m "Release v0.2.0"
```

### 6. Push branch and tag

```sh
git push origin main --follow-tags
```

### 7. Create GitHub release

Navigate to `https://github.com/datenkollektiv/rustyfarian-ws2812/releases/new`:

- Tag: `v0.2.0`
- Title: `v0.2.0`
- Body: paste the `## [0.2.0] - 2026-03-01` section from `CHANGELOG.md`

## Verification

After pushing, confirm:

- Tag `v0.2.0` is visible at `https://github.com/datenkollektiv/rustyfarian-ws2812/tags`
- CI passes on the tagged commit
- Downstream project can reference the new tag in its `Cargo.toml`:
  `ferriswheel = { git = "...", tag = "v0.2.0" }`

## Rollback

If the tag was pushed but a problem is found before any downstream picks it up:

```sh
git push --delete origin v0.2.0
git tag -d v0.2.0
git revert HEAD
git push origin main
```
